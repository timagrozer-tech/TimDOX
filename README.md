# Круг — социальная сеть

Круг объединяет лучшее из ВКонтакте, Одноклассников, Facebook, Instagram и Twitter (X):
дружбу и переписку, ленту записей с фото, реакции, репосты с цитатой, хэштеги и тонкие
настройки приватности. Интерфейс полностью на русском, адаптирован для телефона и компьютера,
есть светлая и тёмная темы.

Это **Этап 1 (MVP)** из технического задания.

## Быстрый старт

### Локально (нужен Python 3.11+)

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # при желании отредактируйте
python -m scripts.seed             # тестовые данные (необязательно)
uvicorn app.main:app --reload --port 8000
```

Откройте http://localhost:8000

Письма (подтверждение e-mail, сброс пароля) без настроенного SMTP не отправляются, а пишутся
в консоль сервера и в файл `data/outbox.log` — ссылку можно скопировать оттуда.

### Через Docker

```bash
cp .env.example .env
docker compose up -d --build
docker compose exec app python -m scripts.seed      # тестовые данные (необязательно)
```

Сайт будет на http://localhost:8000. База и загруженные фото хранятся в томе `krug-data`.

### На своём домене с HTTPS

1. Направьте A-запись домена на сервер.
2. В `.env` укажите `APP_URL=https://ваш-домен` и настройки SMTP.
3. Запустите вместе с Caddy — он сам получит сертификат Let's Encrypt:

```bash
DOMAIN=krug.example.ru docker compose --profile https up -d --build
```

### Тесты

```bash
python -m unittest discover -s tests -v
```

Тесты проходят весь сценарий MVP: регистрация → подтверждение почты → поиск → дружба →
пост с фото → реакция и комментарий → уведомления → хэштеги → приватность → репост и цитата →
сообщения → блокировка → экспорт и удаление аккаунта, а также сброс пароля, лимиты и проверку файлов.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `APP_URL` | `http://localhost:8000` | Адрес сайта (для ссылок в письмах). С `https://` cookie получают флаг Secure |
| `REQUIRE_EMAIL_CONFIRM` | `false` | Запретить публиковать и писать сообщения без подтверждённой почты |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`, `SMTP_TLS` | — | Отправка писем (подойдут Яндекс 360, Mail.ru для бизнеса, Unisender и др.) |
| `DATA_DIR` | `./data` | Папка для базы данных |
| `UPLOAD_DIR` | `./uploads` | Папка для загруженных фото |
| `MAX_UPLOAD_MB` | `10` | Максимальный размер одного фото |
| `SESSION_DAYS` | `30` | Срок жизни сессии |

Список запрещённых слов расширяется файлом `data/banned_words.txt` (по слову или корню в строке).

### Основные API

| Метод и путь | Что делает |
|---|---|
| `POST /api/auth/register`, `/login`, `/logout`, `/verify`, `/forgot`, `/reset`, `/change-password` | Аккаунт |
| `GET /api/feed`, `/api/explore`, `/api/tags/{тег}`, `/api/bookmarks` | Ленты (курсорная пагинация `?cursor=`) |

| `GET / POST /api/posts/{id}/comments`, `DELETE /api/comments/{id}` | Комментарии |

| `POST / DELETE /api/people/{id}/friend`, `/friend/accept`, `/follow`, `/block` | Отношения |

| `GET /api/stream` | Server-Sent Events: `message`, `typing`, `read`, `notification`, `presence`, `counters` |

## Безопасность

- Пароли — `scrypt` с солью; токены сессий и писем хранятся в базе только в виде SHA-256.
- Сессия в cookie `HttpOnly` + `SameSite=Lax` (+ `Secure` на HTTPS).
- CSRF: каждый изменяющий запрос должен нести токен сессии в заголовке `X-CSRF-Token`; запросы с чужого `Origin` отклоняются.
- XSS: пользовательский текст выводится только через `textContent`; строгий Content-Security-Policy без inline-скриптов.
- SQL-инъекции исключены: все запросы параметризованы.
- Ограничение частоты запросов на вход/регистрацию, публикации, сообщения и загрузку файлов.
- Загрузки: проверка типа и размера, декодирование через Pillow, защита от «бомб» распаковки,
  пересохранение в WebP **без EXIF-метаданных (в том числе геолокации)**.
- Приватность проверяется на сервере для каждой выборки: лента, профиль, поиск, теги, фото, комментарии.

## Ограничения и что дальше

Во время разработки у меня не было доступа к npm, поэтому вместо Next.js + Prisma + PostgreSQL + Socket.IO
из ТЗ используется Python (Starlette) + SQLite + Server-Sent Events. Все функции Этапа 1 при этом
реализованы. Что стоит учесть:

- **Масштабирование.** События реального времени хранятся в памяти одного процесса, поэтому
  сервер запускается одним процессом — для старта этого достаточно.
  Для нескольких серверов `app/realtime.py` заменяется на Redis Pub/Sub — интерфейс `publish()` остаётся тем же.
- **База данных.** SQLite в режиме WAL подходит для запуска и небольшой аудитории.
  Для переезда на PostgreSQL нужно заменить `app/db.py` (запросы написаны на стандартном SQL;
  `ulower()` заменяется на `lower()`, поиск — на полнотекстовый индекс `tsvector`).
- **Файлы** хранятся на диске. Для S3-совместимого хранилища (Yandex Object Storage, VK Cloud)
  нужно заменить сохранение в `app/media.py`.
- Фото приватных записей доступны по прямой ссылке (имена файлов случайные и не угадываются).
  Для полной защиты их стоит отдавать через проверку доступа или подписанные ссылки S3.
- Панели модерации пока нет: жалобы сохраняются в таблицу `reports`.

**Этап 2:** сторис на 24 часа, сообщества и паблики, групповые чаты, «Гости», поиск одноклассников
по школе и году выпуска, мероприятия, «Близкие друзья» и «Круги».
**Этап 3:** видео и короткие ролики, голосовые сообщения, лента «Рекомендации» по желанию,
режим «Простой интерфейс» для старшего поколения, PWA, панель модерации.
